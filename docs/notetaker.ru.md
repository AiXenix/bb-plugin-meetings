# Расширенный Notetaker в BB

На странице **Встречи** раскройте **Настройки**. Здесь доступны настройки записи,
шаблоны, аккаунты платформ и подключение внешних агентов.

## Платформы и аккаунты

Поддерживаются Zoom, Google Meet, Яндекс Телемост и Jitsi. Платформа определяется
по ссылке; для своего сервера Jitsi выберите платформу явно или передайте
`bb meetings join <url> --platform jitsi`.

Для встреч с обязательным входом подключите соответствующий аккаунт во вкладке
**Аккаунты**. Вход в Google Meet выполняется отдельно от OAuth Google Calendar.
Пароль вводится в браузере платформы через управление живым экраном. Каждая
встреча получает собственную копию профиля и отдельный аудиоканал. Бот никогда
не выбирает «Переключиться на это устройство» вместо дополнительного подключения.
Имя авторизованного участника Google Meet задаётся самим Google-аккаунтом.

Камера может показывать загруженный или созданный аватар. Исходящая демонстрация
экрана запрещена; получение чужой демонстрации, камера и микрофон работают.

## Запись и календарь

Google Calendar OAuth и ICS ищут ссылки всех поддерживаемых платформ. Автовход
из календаря выключен, пока пользователь его не включит. Для отдельного события
можно запретить подключение. Существующие настройки календаря сохраняются.

В форме подключения можно выбрать шаблон, отключить распознавание или разбор,
задать сообщение в чат. Запись без распознавания сохраняет аудио; позднее можно
нажать распознавание заново. **Остановить** завершает запись, после чего ещё
поступают последние реплики: окончательный разбор и webhook ждут финальный ASR.

**Импорт записи** рядом с формой подключения принимает абсолютный путь к
существующему аудио/видеофайлу на основной машине записи. Сначала файл
подготавливается, затем появляется в общем архиве для распознавания и разбора.
Из терминала: `bb meetings import /full/path/to/recording.mp4`.

## Шаблоны и ИИ

Пять готовых шаблонов: управленческий, продажи, HR, технический и персональный.
Готовый шаблон можно скопировать; свои шаблоны доступны для редактирования и
выбора по умолчанию. Каждый сохранённый разбор содержит точные правила,
использованные при его создании, даже если шаблон впоследствии изменён.

Структурированный разбор включает резюме, решения, риски, темы, главы,
поручения с ответственными/сроками, тональность, follow-up и метрики спикеров.
Поручения можно отмечать выполненными; отметки сохраняются при повторном разборе.
Вопросы по одной или нескольким встречам используют фактические реплики и таймкоды.

По умолчанию работает **Агент BB**: агент, запустивший запись, получает просьбу
прочитать транскрипт и сохранить результат. Кнопка повторного разбора возвращает
полный запрос для агента. Результат появляется после его сохранения, а не после
одного нажатия кнопки. Для внешнего агента `analyze`/`ask` возвращают инструкции,
которые он выполняет через тот же API.

Для непосредственного разбора кнопкой выберите **OpenAI-совместимый API** и
задайте адрес с `/v1`, модель и ключ. Ключ хранится на сервере. Если сервер не
настроен или не ответил, отображается ошибка; выдуманный разбор не сохраняется.

## MCP и REST

Переносимый вариант для MCP-клиента — stdio-адаптер
`integrations/mcp/stdio.mjs`. Он использует установленную команду `bb` (или
`BB_CLI`) и её существующий доступ к BB. Достаточно Node.js; дополнительных
пакетов, публичного порта или токена плагина не требуется. Путь к файлу задаётся
на машине клиента, независимо от пути установки BB:

```json
{"mcpServers":{"meetings":{"command":"node","args":["/path/to/bb-plugin-meetings/integrations/mcp/stdio.mjs"]}}}
```

Проверка доступа: `bb meetings api --request '{"action":"meta"}' --json`.
Для удалённой BB сначала подключите её штатным BB CLI. Плагин не включает
адреса сервера, учётные данные или конфигурацию конкретного внешнего агента.

HTTP-подключение с уже авторизованным доступом к BB:

- MCP: `/api/v1/plugins/meetings/http/mcp`
- REST: `/api/v1/plugins/meetings/http/api`

Для отдельного клиента создайте токен во вкладке **Агенты**. Он отображается
только при создании; повторное создание отзывает предыдущий. На сервере
сохраняется только хеш. Передавайте `Authorization: Bearer <token>`:

- персональный MCP: `/api/v1/plugins/meetings/http/mcp-token`
- персональный REST: `/api/v1/plugins/meetings/http/api-token`

На адресе getbb.app BB Connect проверяет доступ раньше плагина. Персональный
Bearer-токен не заменяет авторизацию BB Connect. Эти HTTP-адреса подходят для
клиента с доступом к BB или собственной настройки входного прокси; для MCP
через штатное удалённое подключение используйте stdio-адаптер.

MCP принимает JSON и заголовок `Accept: application/json, text/event-stream`.
REST принимает один JSON-объект, например `{"action":"templates"}`.
Тот же запрос можно выполнить через `bb meetings api --request-stdin --json`.
Пароли платформ и сохранённые ключи не возвращаются агентам. Для удаления записи
внешний агент должен передать `confirm: true` и точную просьбу пользователя.

Внешние агенты используют собственный доступ через BB CLI.
[Инструкция MCP](https://github.com/AiXenix/bb-plugin-meetings/blob/main/integrations/mcp/README.md).

## Webhook

Настройте URL и секрет подписи. Событие содержит ID, время, сведения о записи,
окончательные реплики и доступный разбор. Большие данные ограничиваются явно:
`transcript.truncated`, `includedSegments` и `analysisTruncated`; оставшуюся
часть можно прочитать через указанные `lookup` действия API.

Подпись в `x-meetings-signature` вычисляется как
`sha256=HMAC-SHA256(secret, timestamp + '.' + rawBody)`.
`x-meetings-timestamp` — Unix-время в секундах, `x-meetings-event-id` — устойчивый
идентификатор события. Получатель должен проверять подпись и время и устранять
дубликаты по ID. Неудачная доставка повторяется после восстановления сервиса;
удаление встречи отменяет её незавершённые запросы.
