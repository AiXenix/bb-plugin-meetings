Cheat sheet written to `/home/bb/bb-plugins/bb-plugin-meetings/docs/dev/sdk-cheatsheet.md`. The code examples in it typecheck against SDK 0.6.37. I also ran the host-entry import paths through `bb plugin build`, and ran Range, CLI, agent tools, host signals and the host harness through the SDK test harnesses. Nothing outside that file was changed.

Top gotchas:
1. **Host imports from the SDK root:** the host build swaps `@get-bb/plugin-sdk` for a stub that exports only `experimental_defineHostEntry`, `defineRpcContract` and `PLUGIN_CLI_OUTPUT_MAX_BYTES`. If anything in the host's import graph, such as `src/shared/*`, imports `PluginCliError`, `defineCli` or `cliCommand`, the build fails. Type-only imports are fine. Importing other helpers from `@get-bb/plugin-sdk/host` requires the SDK in `dependencies`.
2. **Host worker state:** the worker starts lazily and stops after 5 idle minutes, and that idle stop raises no event; only crashes fire `experimental_onWorkerExit`. Use `experimental_retainWorker()` to keep it alive. Keep state in files under `experimental_paths.dataDir`, which here is `/home/bb/.bb/plugins/meetings/host-data`.
3. **Host call limits:** `hostId` is required on every call. The default timeout is 30 s (max 30 min). Output is capped at 8 MiB of JSON, so keep raw chunks at 4 MiB or less once base64 is added. Calls made while the factory itself runs are rejected.
4. **HTTP route paths:** paths are exact-match (`:` and `*` are literal), so pass ids as query params via `c.req.query`. HEAD is not mapped to GET. Streaming `new Response(ReadableStream)` bodies work, and a hand-made 206/`content-range` response was verified.
5. **`<audio>` and `<img>` work with `"local"` auth:** the server only checks the Origin header when one is sent, and these tags don't send it. Use the relative URL `/api/v1/plugins/meetings/http/audio?id=…`. Alternatively, `bb.sdk.files.createPreview` gives a URL with built-in Range support, but it expires (1 hour at most) and is lost when the server restarts.
6. **Runtime imports get bundled:** importing `hono/streaming` (or any package) at runtime bundles it. Git installs skip devDependencies, so every runtime import (zod, ical.js, hono) must be in `dependencies`. Import only types from hono.
7. **CLI option types:** there is no `"number"` type. `integer` needs both `min` and `max`, `duration` needs `defaultUnit` and resolves to milliseconds, and `description` is required on every option. Combined stdout and stderr over 1 MiB is rejected, not cut short.
8. **Required fields in `threads.send`:** `mode` is required, and each text part needs `mentions: []` to typecheck. Use `"queue-if-active"` to notify a thread without interrupting it; `"auto"` and `"steer-if-active"` push into a running turn instead.
9. **Missing icon names:** `Video`, `RefreshCw`, `Users`, `Pencil` and `Loader` don't exist. Use `RotateCcw`, `UserRound`, `Edit`, or `Loading`/`Spinner` plus `animate-spin`, or register your own. Names are case-sensitive, and `IconName` is just `string`, so tsc won't catch typos.
10. **Settings types:** a setting without a `default` is typed `T | undefined`, and select values are plain `string`. Saving settings doesn't reload the plugin, so use `onChange` or call `get()` each time. `useSettings()` never returns secret values.
11. **Status API:** `bb.status` has only `needsConfiguration`; "degraded" and "error" are set by bb. A service must return within 5 s of its abort signal, otherwise the plugin shows as degraded. A `bb` object kept from an earlier load throws after reload, so don't store it at module level.
12. **Migrations are append-only:** never edit or reorder a shipped `bb.storage.migrate` statement. kv values are capped at 256 KB. Database handles close on reload.
13. **Agent tools apply on the next session:** registered tools and instructions take effect when an agent session next starts, never mid-session. Tool names must be unique across all plugins. Without `configure`, every tool is offered.
14. **Frontend RPC:** `useRpc` needs a type-only import of the contract. Use `z.null()` input so the frontend can call with no argument. Navigate inside the page with `useBbNavigate().toPluginPanel("meetings", { subPath })`; `definePluginApp` setup must be synchronous.
15. **Test harness limits:** HTTP auth isn't enforced, services and schedules only run when you call `runService`/`runSchedule`, and any unstubbed `bb.sdk` call throws. Frontend tests need `@testing-library/react`, `jsdom`, `react` and `react-dom` (none installed yet) plus a vitest `@` alias.
